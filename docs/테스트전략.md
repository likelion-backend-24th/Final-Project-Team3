### Sprint Demo 시나리오·Evidence

#### 정상 흐름

- Actor와 시작 상태: 방문자(비로그인) — 승인된 컨퍼런스·세션이 이미 등록되어 있는 상태
- 연결할 Story: Story 1(`#1`), Story 2(`#3`), Story 3(`#20`), Story 4(`#6`)
- 사용자 행동과 확인할 결과: 컨퍼런스를 검색·조회 → 회원가입·로그인 → 세션을 신청해 홀드 생성 확인, 정원이 소진된 세션은 대기열 순번이 부여되는지 확인
- 관련 Test·Evidence: `ConferenceVisibilityTest`, `MemberSignupLoginTest`, `WaitingQueueTest`
- 상태: NOT_RUN

#### 주요 실패 흐름

- 실패 입력 또는 Dependency 상태: 이미 가입된 이메일로 재가입 시도, 세션 정원 조회(`getSessionCapacity`) Timeout, 대기열 순번 미도달 상태에서 결제 API 직접 호출
- 안전한 사용자 결과와 저장되지 않아야 할 데이터: 이메일 중복은 `409`로 거부되고 계정이 생성되지 않는다, 정원 조회 실패 시 `503`으로 거부되고 홀드가 생성되지 않는다(Fail-closed), 순번 미도달 결제 요청은 거부되고 좌석이 확정되지 않는다
- 복구·재시도 기준: 다른 이메일로 재가입 또는 로그인 유도, 클라이언트 재시도 안내, 순번 도달까지 폴링 대기
- 관련 Test·Evidence: `MemberSignupLoginTest`, `CapacityContractFailureTest`, `WaitingQueueTest`
- 상태: NOT_RUN
