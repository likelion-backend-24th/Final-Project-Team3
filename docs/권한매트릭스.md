## 판정 순서

1. 인증 유효성
2. Role
3. Resource 존재와 소유 관계
4. 업무 상태
5. Dependency 결과
6. 허용 또는 안전한 실패

민감 Resource는 추측 방지를 위해 404를 선택할 수 있으며 근거를 기록합니다. 이 Matrix에서는 `getConference`가 해당 — 미승인 컨퍼런스와 존재하지 않는 컨퍼런스를 구분하지 않고 동일하게 `404`로 응답해, 방문자가 "미승인 컨퍼런스가 존재한다"는 사실 자체를 추측하지 못하게 합니다.

Dependency 장애를 권한 없음으로 오인시키지 않습니다. Sprint 1 기준으로 서비스 간 동기 호출이 남아 있는 곳은 `createHold`의 `getSessionCapacity`(Reservation-Service → Conference-Service) 호출뿐이며, 이 호출이 Timeout·오류일 때는 `403`이 아니라 `503`으로 응답해 "권한이 없다"와 "지금 서비스가 응답하지 못한다"를 명확히 구분합니다. `approveConference`·`rejectConference`는 Admin-Service 오케스트레이션 없이 각 도메인 서비스(Member-Service, Conference-Service)가 직접 처리하므로 더 이상 이런 형태의 Dependency 실패 케이스가 없습니다.

Sprint 3부터는 `getAttendeeSummary`의 `getAttendeeCheckinStats`(Conference-Service → Reservation-Service) 호출도 동일한 원칙을 따릅니다 — 이 호출이 Timeout·오류일 때 기존 캐시(`conference_attendee_summary`)가 있으면 `200`으로 캐시를 반환하고, 캐시조차 없으면 `403`이 아니라 `503`으로 응답합니다.
