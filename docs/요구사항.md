## 1. 사용자 문제·Product Goal·성공 기준

| 항목 | 정의 |
| --- | --- |
| 사용자 문제 | 참가자는 관심 있는 IT/테크 컨퍼런스와 인기 세션 정보를 한곳에서 비교·검색하고, 한정된 좌석의 인기 세션을 공정하게 신청할 방법이 없어 신청 실패·중복 결제 같은 혼란을 겪는다. 주최자는 컨퍼런스별로 별도 시스템을 구축할 여력이 없어 세션 신청 접수부터 좌석 관리·정산까지 수기·개별 도구로 처리하며 비효율을 겪는다. 전체관리자는 여러 주최자·컨퍼런스가 한 플랫폼에 공존할 때 승인·과금·정산을 통합 통제할 수단이 없으면 신뢰할 수 있는 다중 임차 운영이 어렵다. |
| Product Goal | 참가자가 원하는 컨퍼런스와 세션을 안정적으로 검색·신청·입장할 수 있고, 주최자가 자신의 컨퍼런스를 독립적으로 운영·정산할 수 있으며, 전체관리자가 여러 주최자·컨퍼런스를 하나의 플랫폼에서 통합 승인·감사·정산할 수 있는 상태에 장기적으로 도달한다. |

### Release 성공 기준

- 참가자가 회원가입 후 컨퍼런스·세션을 검색하고 세션 정원 내에서 결제까지 완료해 QR 티켓을 발급받을 수 있다.
- 정원을 초과하는 동시 신청 요청이 몰려도 확정 신청 수가 세션 정원을 넘지 않고, 초과 인원은 대기열로 처리된다 (권한·소유권·거래 일관성).
- 주최자가 컨퍼런스를 등록 신청하고, 전체관리자 승인 후에만 참가자에게 공개되어 신청을 접수할 수 있다.
- 결제 실패·취소, 정원 초과, 미승인 컨퍼런스 접근 같은 실패 흐름이 정상 흐름과 함께 검증된다.

## 2. 대상 사용자·Release 범위

### 대상 사용자

| Actor | 목표·책임 |
| --- | --- |
| 방문자 | 회원가입 전 컨퍼런스·세션 목록·상세를 조회하고 참가 여부를 판단한다 |
| 참가자(Member) | 회원가입 후 세션을 신청·결제하고 QR 티켓으로 입장하며, 필요 시 취소·환불을 신청한다 |
| 주최자(Organizer) | 사업자등록번호 인증을 거쳐 스스로 계정을 발급받아 자신의 컨퍼런스·세션을 등록·운영하고 정산 내역을 확인한다 |
| 전체관리자(ADMIN) | 컨퍼런스 승인·결제 정산·통합 통계·시스템 설정을 통해 플랫폼을 운영한다 |

### 범위

| 구분 | 내용 |
| --- | --- |
| 현재 Release | 컨퍼런스·세션 조회·검색, 회원가입/로그인, 세션 신청·결제·QR 티켓 발급, 세션 정원 초과 방지와 대기열, 컨퍼런스 등록 신청→승인→운영, 신청 취소·환불(기한 내), 전체관리자의 컨퍼런스 승인·결제 정산 현황 조회 |
| 후속 Product Backlog 후보 | 스폰서 배너 노출 신청·과금(舊 VIP 배너), 계정/권한 감사 로그 조회, 다국어 콘텐츠 노출 |
| 제외 범위 | 스폰서 배너의 자동 과금·정산 연동, 이메일/SMS 알림 템플릿 발송, 리뷰·평점 |
- 소비자(참가자)의 신청·이용뿐 아니라 공급자(주최자)의 컨퍼런스 생성·운영, 운영자(전체관리자)의 승인, 거래의 취소·환불·정산까지 제품에 필요한 흐름을 점검했습니다.
- 후속 후보는 요구사항이 확정되었다는 뜻이 아닙니다. 실제 Product Backlog의 순서·크기·상태는 GitHub Project에서 계속 정제합니다.
- GitHub Project의 Item 목록·순서·Sprint·상태는 이 Notion 요구사항이나 `product_backlog.md`에 복제하지 않습니다.

| <a id="결제완료-기준집계"></a>집계는 결제 완료 상태 기준으로만 계산된다 | 대기·취소 상태 신청은 통합 통계에 포함되지 않는다 | 시나리오 15 |
| <a id="pg키-비공개"></a>PG 키(Secret)는 문서에 기록하지 않는다 | Notion·Git 문서·커밋 이력에 평문 키가 존재하지 않는다 | 시나리오 16 |

구현 패턴, Service·DB 소유권, API, Test 이름은 각각 설계·계약·Test 문서에 기록하고 이 절에는 제품이 지켜야 할 결과만 둡니다.

## 5. 업무 용어

| 업무 용어 | 제품에서 사용하는 의미 |
| --- | --- |
| 컨퍼런스(행사) | 주최자가 등록하는 신청 대상 IT/테크 행사 단위 |
| 세션(트랙) | 컨퍼런스 내에서 별도 정원으로 운영되는 발표·강연 단위 |
| 세션 정원 | 하나의 세션에 확정 가능한 최대 신청 수 |
| 대기열(Virtual Waiting Room) | 세션 정원 초과 시점에 신청을 시도한 참가자가 순번대로 대기하는 상태 |
| 홀드(Hold) | 결제 완료 전, 좌석·인원을 임시로 점유해 중복 판매를 막는 상태 |
| QR 티켓 | 결제 확정 후 발급되는 1회성 입장 인증 코드 |
| PG(Payment Gateway) | 결제 대행사. 실제 카드사·은행 결제를 중계하는 외부 서비스 |
| 정산 | 결제 완료 건을 기준으로 주최자에게 지급할 매출·수수료를 계산하는 절차 |
| 스폰서 배너 | 주최자가 과금하여 노출 순위를 높이는 광고 슬롯 (후속 후보, 舊 VIP 배너) |
