## **새 clone 실행**

```html
cd infra
cp .env.example .env
# .env를 열어 위 표의 필수 항목을 채운 뒤
docker compose config
docker compose up --build
```

`infra` 디렉터리 안에서 실행해야 `compose.override.yaml`(로컬 전용 포트 오버라이드)이 `compose.yaml`과 자동으로 합쳐짐. 저장소 루트에서 `docker compose -f infra/compose.yaml up`처럼 `-f`로 단일 파일만 지정하면 override가 자동 적용되지 않으니 주의.

로컬 MySQL(Windows `MySQL80` 서비스 등)이 이미 3306 포트를 쓰고 있으면 컨테이너 기동이 실패함 — 먼저 `net stop MySQL80`(관리자 PowerShell)으로 로컬 서비스를 내려야 함.

## **프로덕션 배포(EC2 + GHCR)**

GitHub Actions가 각 서비스 이미지를 빌드해 GHCR에 올려두면, 서버에서는 소스 빌드 없이 이미지만 pull한다.

```
cd infra
docker compose -f compose.yaml -f compose.prod.yaml pull
docker compose -f compose.yaml -f compose.prod.yaml up -d
```

프론트는 443(HTTPS, Let's Encrypt) 포트로 뜨고, `certbot` 컨테이너가 인증서 발급·갱신을 전담(평소엔 내려가 있어도 됨).

## **중지·재기동·데이터 초기화**

| **명령** | **영향** | **복구 가능성** |
| --- | --- | --- |
| `docker compose stop` | 컨테이너만 멈춤, `mysql_data` 볼륨·업로드 파일 그대로 유지 | `docker compose start`로 그대로 복구 |
| `docker compose up --build -d` | 이미지만 다시 빌드해 재기동, 데이터는 유지 | 안전(반복 가능) |
| `docker compose down` | 컨테이너·네트워크 제거, 볼륨(`mysql_data`, uploads)은 남음 | `docker compose up`으로 재기동하면 데이터 그대로 복구 |
| `docker compose down -v` | **볼륨까지 삭제 — DB 데이터 전부 유실, 되돌릴 수 없음** | 복구 불가. 정말 초기화가 필요할 때만, 사전에 백업 없다면 신중히 사용 |
